Mapping Climates

The core engine is a mapping object that translates API responses into UI states.
Weather → Mood → Outfit → Assets → Environment
Each condition triggers a specific visual configuration.
This allowed the UI to stay modular, scalable, and extendable.

Atmosphere, Engineered

All environmental effects are built in native CSS.
Rain (3 intensities), Snow & hail particles, Lightning flashes, Fog overlays, Wind motion, Character micro-animations.

No animation libraries.
No canvas hacks.
Just layered performance-conscious motion.

    100% { background-position: 200px 1000px; }

The Process

Started as a simple exercise to map Figma variables to design tokens.

It started as play.

I began experimenting in Google Whisk, modifying an existing character illustration to see how it could adapt to different climates.

What if the same character could feel sunny, rainy, cold, or stormy — just by changing variables?

That question became the seed of the system.

Whisky

Designing the System in Figma

The next step wasn’t code — it was structure. In Figma, I designed the main screen and defined color variables for each climate state: Sunny, Rainy, Cloudy, Night.

Instead of creating separate screens, I built modes. I explored:

• Color tokens per climate
• Outfit variations per condition
• Background atmosphere layers
• Component states tied to logic

The character wasn’t just decorative. It became reactive.

Figma

From Figma to Code

Using Figma MCP, I exported the design into Antigravity.
From there, the goal was clear: recreate the entire system using pure CSS animations.
No animation libraries. No shortcuts.

Rain, lightning, fog, snow — all layered and performance-conscious.

The logic was mapped so weather API responses triggered:

Weather → Mood → Outfit → Assets → Environment

Antigravity

Shipping It

The final step: deployment.

The project was versioned and published through GitHub, turning a playful experiment into a live product.
